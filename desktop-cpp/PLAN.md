# The C++ port of Palm Desktop

The port moved the Rust desktop app in `desktop-rs/` to C++23 and FLTK in `desktop-cpp/`. It followed the phases of `desktop-rs/PLAN.md`, and each module ports its Rust file line by line. Since the cutover in 0.24 the C++ app is the shipped desktop app; `desktop-rs/` and its CI job stay as the reference of the screenshot check, and a UI change goes into both apps.

## Build

- CMake 3.25 or newer, Ninja, and g++ 14 (C++23): `cmake -S . -B build/all -G Ninja`, `cmake --build build/all`, `ctest --test-dir build/all`. Warnings are errors.
- Libraries: OpenSSL (AES-GCM, PBKDF2, SHA-256, random), zlib (raw deflate), libcurl (palmsync), nlohmann/json, and doctest. This Windows machine takes them from MSYS2 mingw64 (`C:/tools/msys64/mingw64/bin` first on PATH); CI uses MSYS2 MINGW64 on Windows and g++-14 on ubuntu-24.04.
- `CMakeLists.txt` lists the core and app modules in dependency order with the libraries each links. Each `core/tests/test_<name>.cpp` and `app/tests/test_<name>.cpp` is its own test program; its first line names the modules it links (`// links: model codec`), read at configure time.
- `palm/text.hpp` holds the helpers for what Rust's `str` and `char` have built in (UTF-8 code points, White_Space, `trim`, `split`, case mapping, `from_utf8_lossy`). A module uses them and keeps no copy of its own.
- `clang-format` 20 with `.clang-format` (tabs, 120 columns); the CI job checks `core/` and `app/` on linux-amd64.

## Port rules

- Names stay as in Rust (snake_case functions, PascalCase types); a name that is a C++ keyword takes the module name (`export_ical`, `export_vcard`, `SyncClient::new_client`).
- `Result<T, String>` is `std::expected<T, std::string>`, `Option` is `std::optional`, a Rust enum with data is a `std::variant`, a trait is an abstract class, and a Rust panic is a thrown `std::runtime_error`.
- Rust's `div_euclid`, `rem_euclid`, and `%` on negatives differ from C++; Rust iterates `char`s where C++ sees bytes. Each port checks both.
- Case mapping is Rust's over all of Unicode, the final sigma of `str::to_lowercase` included: `core/src/text_case.inc` is generated from the Rust standard library by `tools/gen_case` (`cargo run --manifest-path tools/gen_case/Cargo.toml > core/src/text_case.inc`); regenerate it with a newer Rust when the Rust app moves to a newer Unicode.
- `json::parse_value` is a port of serde_json 1.0.154's reader with its default features: the same values (floats too: without `float_roundtrip`, serde_json scales the significand by a power of ten, which can miss the nearest double in the last bit) and the same error texts and positions. `json::dump` writes floats as serde_json does (zmij: `format_double`). A file that Rust reads with `read_to_string` must be UTF-8 (`text::is_utf8`). When serde_json is upgraded, rerun a differential check of both readers on many texts, as on 2026-11-04 (6,079 texts, no difference).
- Pixels: FLTK builds as fltk-sys builds it (GDI+ on Windows, FLTK at the compiler's default standard, so GCC fuses multiply-adds in FLTK on arm64 as under fltk-sys), and our code builds as ISO C++23 with `-ffp-contract=off`, as Rust fuses none. Take screenshots from a Release build: fltk-sys builds FLTK at -O3.
- Time zones use C++20 `<chrono>` (`locate_zone`). `platform::local_zone()` gives the user's zone: `TZ` as jiff reads it, else on Windows `GetDynamicTimeZoneInformation` mapped through the CLDR table in `platform.cpp` (generated from jiff 0.2.38's copy; regenerate it from a newer jiff), else `current_zone()`. Under MinGW `current_zone()` gives `Etc/UTC`, so never call it directly.
- Test the store with copies: `PALM_REAL_DATA=<folder> build/all/test_store.exe` reads `desktop-data.json` (and `desktop.properties` when present) from that folder and writes only to a temp folder. The fixture is read from `desktop-rs/app/tests/fixtures`; move it into `desktop-cpp/app/tests` before `desktop-rs/` goes.
- `json::dump` writes every JSON text; it replaces invalid UTF-8 with U+FFFD, so a save never throws. OS errors read as Rust shows them, through `platform::os_error_text`.
- The client follows no redirect, and on Windows it takes the system certificate store (`CURLSSLOPT_NATIVE_CA`).
- Date arithmetic on stored values wraps (`days::wrapping_add` &c), as the Rust release build and Kotlin's `Long` do; signed overflow is undefined in C++.
- UI modules (app/src, linked with FLTK 1.4.5) port fltk-rs line by line to the FLTK C++ API: `fltk::button::Button` is `Fl_Button`, `window::Window` is `Fl_Double_Window` (fltk-rs makes `Window` an alias of `DoubleWindow`, so every Rust window is double-buffered), `menu::Choice` is `Fl_Choice`, and so on. A group owns and deletes its children, so code keeps raw pointers to child widgets; a label that is built at run time goes through `copy_label`/`copy_tooltip`.
- Every widget callback, timer and worker thread sends a `Msg` through `msg::Sender` (a mutex-guarded queue and `Fl::awake`), and the main loop handles it; no callback touches the app state, as in Rust.
- A Rust `handle` closure becomes a subclass that overrides `handle(int)`. fltk-rs runs FLTK's own handler first and then the closure, unless the Rust calls `super_handle_first(false)`; the override keeps that order. Mouse buttons compare `Fl::event_button()` with `FL_LEFT_MOUSE` and `FL_RIGHT_MOUSE`. A Rust `draw` closure becomes an overridden `draw()`.
- Custom drawing goes through `draw::Dev` (FLTK's `fl_override_scale`) and clips through `draw::Clip`, as in Rust. The 3.1.1 bitmaps come from `assets::png(name)` as an `Fl_PNG_Image` built from the bytes.
- Rust code that adds a handler to an existing widget becomes a subclass that the caller builds in its place: a Choice given `combo::drop_below` is a `palm::combo::Choice`; a text field given the text-field menu (`text_edit::attach_menu`) is a `palm::text_edit::Editor` (Fl_Text_Editor) or `palm::text_edit::Input` (Fl_Input). `text_edit::Field` is `std::variant<Fl_Text_Editor*, Fl_Input*>`. A record list (a Rust `TableRow` passed to `records::list_event`) is a `palm::records::RecordTable`, an `Fl_Table_Row` that can find the cell under the mouse.
- UI modules keep their Rust tests that need no display, in `app/tests/test_<module>.cpp`.
- Known limits: libstdc++ 14.2 under MinGW misreads negative LMT offsets, so a TZID time before a zone's standard time (c. 1883 in the U.S.) lands off by up to two hours; seen on Windows; Linux, whose libstdc++ reads the same tzdata.zi text form, is unchecked. A POSIX rule in `TZ` ("EST5EDT,M3.2.0,M11.1.0") falls back to UTC, where jiff applies it; so does a `TZ` that names a TZif file, which jiff reads.
